⚡ Slipstream — component & request-flow block diagram

Two processes, one pipe. Green = request path, blue = token return path. Numbered badges trace one /v1/chat/completions call end to end.
1 HTTP in — route, auth, deadline set (server.py)
2 Prepare — chat template, image resize, tokenize (frontend.py)
3 Submit — request object with priority + deadline (backend.py)
4 Frame encode — token ids + pixels → binary frame (protocol.py)
5 Pipe — frame written to native child stdin
6 Admit — engine takes ownership of the request
7 Prefix lookup — KV + recurrent-state cache → resume boundary
8 Resource grant — memory governor grants KV pages
9 BatchPlan — scheduler issues prefill chunk / decode step
10 Execute — draft → verify → accept; ops → Metal → GPU
11 Expert streaming — missing MoE experts read from SSD in waves
12 Stream out — token frames → pipe → SSE chunks → client
