The Big Picture

Chapter 01 · The six layers, the pipe boundary, and the dependency rules.

Slipstream is a two-process system. A Python server speaks HTTP and shapes requests; a native C++/Metal engine does the actual inference. They talk over a binary pipe. Everything model-specific lives in its own folder. The diagram below is the whole system.

Dependency Rules enforced by dev/tools/check_architecture.py

Model folders launch their own kernels
Shared model code may not — model-specific GPU work stays in one place.
Models never depend on the engine
…or on another model. Models stay swappable.
Shared ops/metal never depend on a model
Shared code stays shared.
Engine never names a concrete model
Except its startup files. Scheduling & memory policy work for any model.
Honest limit: the shared runtime (Runtime.mm, state, arenas) assumes the Qwen hybrid family — linear-attention and full-attention layers, an 8-bit paged KV cache, and a recurrent state per request. A model from this family plugs in as described. A model outside it (e.g. pure attention with a different cache) also needs the runtime's buffers and state generalized. That work is not done.
