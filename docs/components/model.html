Qwen3-8B Architecture

64 layers in a hybrid pattern: most layers use GDN (Gated Delta Network — linear attention with recurrent state), every 4th layer uses full attention (paged KV). This is why the engine needs both a recurrent state cell AND a KV page pool per request.

Decode Loop (per request)

DraftDFlashDraft
The small draft model proposes maxSimulationTokens (≤32) candidate tokens using captured hidden states from the target. Runs on the same GPU, different Metal graph.
VerifyQwenTarget (verify path)
The target model scores all draft candidates in one parallel pass (Q8VerifyAttentionParams — up to kQ8VerifyMaximumRows rows, split across kQ8VerifySplits). Produces per-position acceptance probabilities.
Acceptsampling + commit
Greedy or sampled acceptance: walk the draft, accept while target probability exceeds threshold, then sample one bonus token from the target distribution. Accepted tokens commit to the KV cache; the recurrent state advances by the accepted count.
Commitstate + KV update
Write new KV pages for accepted tokens, advance the GDN recurrent state, update the draft context. If a tool-call boundary is hit, emit a MaskRequest and pause.

Qwen4-Exp Extensions

Hyper-Connection
Replaces the standard residual stream with a learned mixture of multiple parallel streams. The mix weights are stored 8-bit in a tiled matrix layout (HyperConnection.h ABI). This is a Qwen4-Exp-specific kernel — it lives in the model folder, not in shared ops.
Per-Layer Embedding
Each layer has its own input embedding projection (PerLayerEmbedding.h ABI) instead of sharing the base embedding. Reduces interference between layers at the cost of extra weight memory.

State Layout

CompositeState
Per-request recurrent state, allocated as one contiguous block:
ComponentContentSize driver
Target recurrentGDN linear-attention state (key/value head states + conv buffers)48 GDN layers × (16k + 48v) heads × 128 dim
Draft contextDraft model's own recurrent state + captured hidden statesDraft layer count × hidden size × capture count

The state is per-request (not per-batch) — each lane in a decode batch has its own state cell. The StateCache in the engine attaches these to KV blocks for prefix reuse.

Dependency rule: Model folders may depend on runtime/model/, runtime/ops/, and runtime/metal/. They may not depend on runtime/engine/ or on another model folder. Model-specific Metal kernels live in the model folder; shared kernels live in runtime/metal/kernels/.
