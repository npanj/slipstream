Layered Structure

The Tick Loop Engine::tick(now)

Everything in the engine happens from one heartbeat. NativeRuntime calls tick() after every drained pipe frame and after every GPU command completion. The loop is strictly ordered:

1 · Health checkmodel_.checkHealth()
At most once per second (kHealthCheckIntervalMilliseconds = 1000). The model reports GPU/driver health; a failure fails all in-flight requests.
2 · Expire deadlinesscheduler_.expireDeadlines(now)
Any non-terminal request whose deadlineMilliseconds has passed → Phase::Failed. Finalized immediately (even mid-command) so late masks/cancels become no-ops.
3 · Resource-wait timeoutsper active request
Requests in WaitingResources past resourceWaitTimeoutMilliseconds (default 30 s) → failed with resource_timeout. Skipped entirely while drainingForRecovery() — suspended peers must finish first.
4 · Sweep terminalsweepTerminal()
If anything changed: remove terminal requests from the scheduler and requests_ map, releasing their state cells and cache references.
5 · Pending command in flight?pending_ != nullopt
  • Forward any MaskRequests the model ticket took (engine pauses in WaitingMask until Python answers)
  • On command completion: apply(plan, results) — commit KV writes, advance phases, emit token events
  • Clear pending_, take the next batch
6 · Admit queued workadmitQueued(now)
  • While recoveringResources_: only retry suspended requests, one lane at a time (prevents B4 admission/preemption churn)
  • Otherwise: walk admissionOrder() (priority, then arrival order) and admit() each
7 · Take next batchscheduler_.next()
If no command is in flight: pick the next BatchPlan (decode preferred over prefill at equal priority, alternating at command boundaries), prepare() it, dispatch to the model.

Request Admission Engine::admit()

Admission is a transaction: either the request gets its state cell + KV pages and starts, or it goes to WaitingResources with a retry. Nothing is half-committed.

Cache lookupcache_.lookup(...)
Content-addressed search: how many prompt tokens are already cached? Returns CacheLookup { kvBoundary, state } — the longest reusable KV prefix plus an optional recurrent-state lease (resume boundary). A resume skips re-prefilling everything before the state boundary.
Model beginmodel_.begin(request)
Allocates the request's recurrent state cell (Qwen linear-attention state, draft context). Fails with StateFailure::MemoryPressure or ConcurrencyLimit → request goes to WaitingResources.
KV page acquisitionadmitKv(active, workEnd)
Acquires physical KV pages for the work window. On failure: TokenAdmission carries the failure class. budgetMayRecover() checks the governor — if host pressure is the cause, the request waits; if it's hard capacity, it fails with CapacityExhausted.
Suspend / resumesuspendForGrowth()
Under memory pressure, a running request can be suspended: its state cell is evicted to the StateCache, KV pages released, phase → WaitingResources. On retry it resumes from the exact token boundary (active.exactTokens) with restored state. Provisional in-flight writes are invisible until the command drains, so suspension is safe.
State boundaries armedconfigureStateBoundaries()
Checkpoints (every prefillCheckpointTokens, default 4096) + replay boundaries (page-aligned) + junctions (where a cached prefix ends mid-prompt). These are the points where the engine publishes reusable state into the cache.

Scheduler: Phase FSM

Batch Packing Rules

Prefill packing
Shortest-remaining-first into an actual-row budget (prefillChunkTokens rows per command). A lane yields to later arrivals after at most maximumBatchWidth − 1 consecutive prefill commands (kMaximumOvertakes) so no lane starves. Contended prefills (>500 ms) shrink the budget; minimum 64 rows.
Decode packing
Fixed-width batches up to maximumBatchWidth (env SPLASH_MAX_BATCH_WIDTH). Cohorts: Greedy / Sampling / Constrained — a batch is one cohort only. DecodeStage::ApplyInitialMask requests are classified one at a time (they can terminate or start drafting); regular decode batches freely.
Kind alternation
Prefill and decode use different Metal command graphs and cannot share a command. next() honors request priority first, then alternates kinds at command boundaries so equal-priority work interleaves fairly.
Deadline enforcement
Deadlines are checked every tick, not at dispatch. A request that expires mid-batch still runs its in-flight command (a Metal command can't be revoked) but its results are discarded — provisional writes never publish.

ExtentContiguous run of pages in one Metal allocation. Free pages are handed out from the extent with the most free space first (packingExtent_), so a burst of allocations rescans extents only when it moves into a new one.
FreeClassEach page is FreeUnbacked (no Metal memory), FreeResident (mapped, cheap to reuse), or in use. Free lists are intrusive linked lists (previousFree/nextFree).

KvCache — Content-Addressed Block Graph

Blocks are keyed by (parentBlock, indexHash, tokens, images) — a hash-filtered, equality-verified prefix tree over whole KV pages. One process = one CacheNamespace (SHA-256 of the loaded model + build + Q8 layout), so blocks never mix models.

Lookup
Walks the prompt page-by-page from the root. Returns the longest cached prefix (kvBoundary) and, if a StateCache lease is attached to the block at that depth, the recurrent state too (resumeBoundary). The junction between the two is where a "lazy junction" materialization may be needed.
Eviction
An EvictionOrder set ordered by recency (via CacheRecency). Blocks with children are never evicted (their descendants reference them). Eviction releases the physical page back to the pool but keeps the block's logical identity for future re-residency.

StateCache — Recurrent State Leases

Atomic target+draft state
Attaches one immutable target-recurrent + draft-context state pair to a complete target-KV block; the pair is restored atomically. This is what makes resume cheap: a request that finds a cached prefix with an attached state skips re-prefilling and re-warming the linear-attention state. Evicted states park their buffers in the model's pool; a pressure pass returns that memory to the host.

Memory Governance

MemoryGovernor — the ledger
The sole physical-memory admission ledger. It does not allocate, evict, or schedule — it only hands out short-lived byte Reservations (RAII: commit or release on scope exit) to callers about to commit a placement heap. Keeps policy out of MetalBackend and makes every growth transactional. Tracks reservedBytes_, deniedReservations_, and effective pressure.
Pressure policy
Host available memory = physical − used pages, crediting pageable file-backed and purgeable pages. Three levels: Normal → Warning (growth stops within the reserve margin; paced cache-shedding passes) → Critical (drop every evictable thing). MemoryPressurePolicy::update() emits bounded MemoryReclaimDirectives separated by a telemetry settling interval — new pressure is never offset by bytes reclaimed earlier in the same episode.

Reclaim Cascade Engine::reclaimMemory(directive)

1 · Model idle statemodel_.reclaimIdleState()
Evicted requests' state cells return their buffers to the model's buffer pool. Loops until the model reports nothing more idle.
2 · Cache evictioncache_.reclaimCache(remaining, evictAllUnpinnedPrefixes)
Evicts KV blocks in recency order until the directive's targetBytes is met. Critical pressure also evicts unpinned prefixes. Even a zero-byte directive releases completely empty extents.
3 · Return to hostmodel_.reclaimIdleState() again
Evicted states parked in the model pool are returned to the host now rather than kept warm. Then signalResourceProgress() bumps resourceEpoch_ so waiting requests retry immediately instead of their backoff timer.

Apply & Finish Engine::apply(plan, results)

Validate resultsapply()
Result count must match plan width; each result.requestId must match its plan item in order. A request that failed mid-command (cancel/deadline) still gets a result slot, but its provisional writes are discarded — no cache publication, no token emission.
Publish state boundariespublishReachedStateBoundaries()
As tokens cross armed boundaries (checkpoint / replay / junction), the engine publishes the new KV block + state into the cache. Deduplication: a boundary already published by a peer request is a no-op (deduplicatedStatePublications counter). Recycled publications (after reclaiming a cached state) are counted separately.
Advance phasesscheduler_.complete(...)
Prefill → Decode (or terminal if the prompt ended on a stop token). Decode → Decode, or WaitingMask (model requested a mask), or terminal (stop token / max tokens). Emits Tokens events to the EngineEventSink → protocol frames → pipe → Python → SSE.
Finish & releasefinish() → release()
Terminal: emit Done/Error/CapacityExhausted, release the state cell, release KV page references (blocks stay in the cache graph for reuse), remove from requests_. sweepTerminal() does the map removal on the next tick.

Compares actual post-warmup memory against the plan. On failure the full BudgetValidationStatus JSON is reported instead of a partial instance.

Emits the binary Ready frame. No partially warmed instance escapes start() — the Python side only accepts the engine after this frame.

Process Plumbing

FdTransport
POSIX pipe, nonblocking only while run() is active. Each iteration drains all already-available frames before advancing the backend — so mask responses can arrive while the target-forward command is in flight. A control-wake fd lets paced work (one KV extent release at a time) continue without a new notification. requestShutdown() is async-signal-safe. Exit codes: 0 clean EOF, 64 protocol, 70 engine, 74 IO.
NativeRuntime
Translates protocol messages at the Engine boundary. Tracks per-request telemetry (arrived / started / first-token / last-token / emitted count). holdingRequests callback tells main.mm to suppress Mac idle sleep between requests. Owns the EngineEventSink → frame emission.
Dependency rule: the engine never names a concrete model. It depends only on model::Model (begin / prefillAsync / decodeAsync / suspend / resume / restore / reclaimIdleState / checkHealth) and ops:: types. Scheduling and memory policy work for any model that implements the interface.
